# Experimental Design – Randomized Block Design (RBD)

**Project:** Daily Electricity Consumption Prediction in Smart Buildings (BDG2)

---

## 1️⃣ What is a Randomized Block Design?

- **Blocks:** Groups of experimental units that are expected to be similar. In our case, each **building** (identified by `building_id`) is a block because buildings differ in size, usage, climate, and other characteristics.
- **Treatments:** The predictive models we want to compare.
  - **Control (baseline) treatment:** Linear Regression
  - **Experimental treatments:** Random Forest Regressor, Gradient Boosting Regressor
- **Goal:** Compare model performance **within each block** and then aggregate the results, reducing variance caused by building‑specific effects.

### Why RBD fits this project?
| Reason | Explanation |
|--------|-------------|
| Heterogeneous buildings | Different floor areas, primary uses, and climate exposure can cause large variation in electricity consumption. By blocking on `building_id`, we control for these differences. |
| Limited number of treatments | Only three models – easy to randomize and evaluate. |
| Chronological time‑series data | Splits (train/val/test) are done **chronologically** to avoid leakage, but the block structure remains the same across time.

## 2️⃣ Experimental Structure

| Component | Value |
|-----------|-------|
| **Blocks** | All 1,440 eligible buildings (`building_id`). |
| **Treatments** | `LinearRegression` (control), `RandomForest`, `GradientBoosting`. |
| **Randomisation** | For each block, we **randomly assign** one of the three treatments *once* – the assignment stays fixed for the whole time series of that building. This mimics a classic RBD where each block receives a single treatment. |
| **Evaluation metric** | MAE, RMSE, R² on the **chronological test period** (2017‑07‑01 → 2017‑12‑31). |
| **Statistical testing** | Paired comparison (e.g., Wilcoxon signed‑rank) of model errors **within blocks**. |

## 3️⃣ Implementation Blueprint (`src/experimental_design.py`)

The script performs the following steps:
1. Load the **feature dataset** (`features_dataset.parquet`).
2. Extract the unique `building_id` values → our block list.
3. Randomly assign one of the three treatments to each block (seed = 42 for reproducibility).
4. Save the mapping to `data/processed/experimental_design_info.csv`.
5. Optionally, split the data **chronologically** into train/val/test while keeping the block‑treatment mapping for later model‑training scripts.

The actual model training (Phase 8) will read this file to know which model to train on which building.
